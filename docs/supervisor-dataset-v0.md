# Supervisor dataset v0: benchmark fit and remaining evidence

## Decision

The current sources are sufficient for a first small supervisor model, but only
when they are used as separate evidence layers. They are not interchangeable:

| Layer | Current size | What it can teach | What it cannot teach |
|---|---:|---|---|
| Generic chooser corpus | 13,207 tasks | Static task difficulty and family | In-run progress or current-model quality |
| Nemotron Terminal Corpus | 356,199 unique tasks / 366,154 trajectories | Terminal competence and benchmark-aligned task mix | Counterfactual model choice |
| Benchmark-gap companions | 2,406 task records | Games, ML, optimization, and workplace tool use | A unified terminal policy by themselves |
| Aligned task panel | 1,950 unique source-train tasks | Exact category proportions for the frozen benchmark | Training text until prompts are materialized |
| Three-source dynamic set | 160,279 checkpoints / 18,988 task records | Stage and completion recognition across terminal, broader agent, and SWE harnesses | Switch, cost, or failure-recovery labels |
| Matched multi-model rollouts | Not collected yet | Continue/switch/stop decisions and completion/cost tradeoffs | Nothing until the same checkpoints are run across models |

The immediate training-ready dynamic set has 119,925 train checkpoints, 15,908
validation checkpoints, 16,732 internal-test checkpoints, and 7,714 sealed-test
checkpoints. Splits are grouped by normalized task description, so turns or
duplicates from one task cannot leak across sources or splits. Training impact
is weighted 60% NVIDIA terminal, 20% OpenThoughts, and 20% NVIDIA SWE; raw row
count does not determine product priority.

## Benchmark relationship

The final benchmark remains the digest-pinned 30-task Terminal-Bench 2.1 sample
in `benchmarks/terminal-bench-2.1-gate7.json`. It contains 20 medium and 10 hard
tasks across 15 categories.

The Nemotron Terminal Corpus directly covers 25 of those 30 category seats. Its
missing exact categories are games, machine learning, optimization, and
personal-assistant work. Pinned companion sources fill all four:

- 78 game tasks from Harbor-packaged Reasoning Gym easy/hard;
- 817 machine-learning tasks from SETA's Kaggle environments and ML-Dev-Bench;
- 256 optimization tasks from AlgoTune and GSO;
- 1,255 training examples from NVIDIA's workplace-assistant environment.

`data/supervisor/aligned-task-panel-v0.jsonl` selects 65 source-train examples
per frozen-benchmark seat: 65 for a one-seat category, 130 for two seats, 195
for three, and 260 for four. This produces 1,950 unique task references whose
category distribution exactly matches the frozen sample. Sixty-five is not a
magic industry number; it is the current clean bottleneck imposed by the game
pool while retaining separate source validation and internal-test tasks.

This proportional panel is a sampling manifest, not yet a text training file.
It deliberately retains no task instructions, solutions, tests, or verifier
answers. Prompt materialization must read only the selected instructions and
keep solutions/tests behind the verifier boundary.

## Why the volume is credible

The public evidence suggests that quality and alignment matter more than one
universal row count:

- NVIDIA reports Terminal-Bench 2.0 improvement from its Terminal Corpus across
  Qwen3 8B, 14B, and 32B workers.
- OpenThoughts reports useful Terminal-Bench and SWE-bench transfer from roughly
  10,000 verifier-confirmed trajectories per source.
- SETA reports Terminal-Bench transfer from 4,567 executable environments.
- The combined set supplies 160,279 state/action examples. Its learning curve
  rises from 78.9% average precision at roughly 60,000 training checkpoints to
  80.4% at roughly 120,000.

For this product, another 100,000 generic prompts would add less information
than 50–100 tasks run on every candidate model. The scarce label is comparative
outcome under the same state, not task text.

## Leakage boundary

The generated checkpoint input contains only information available at decision
time:

- task identity through a task-table join;
- turn index and already-observed history counts;
- newest terminal output statistics and a 4,096-character tail;
- error, pass, test, and shell-prompt signals.

The teacher's next commands, analysis, and plan are converted into derived
labels and then discarded. Total source trajectory length is post-run
information and appears only under `audit_only`, never under `input`.

The source has 630 task names but 631 distinct task descriptions because
`hpc-shadow-pipeline` names two different tasks. The builder keys splits by both
name and description hash to prevent the collision from merging unrelated
examples.

## The key limitation

All retained checkpoints come from successful or high-confidence trajectories
generated by a small number of teacher families. They can teach the model to
recognize stages such as inspection, editing, validation, execution, waiting,
and completion. They cannot show that Qwen, DeepSeek, Kimi, or GLM would have
been the best next model.

The model-choice target therefore comes from a separate matched panel:

1. freeze a task and observable checkpoint;
2. branch the same state to each candidate model;
3. record completion, verifier evidence, new progress, tokens, cost, and time;
4. label the cheapest model among models meeting the completion requirement;
5. retain all outcomes so the product can move along the empirical Pareto curve.

The first paid pilot should be small and stratified. Its purpose is to validate
the feature/label pipeline and estimate variance, not to claim a production
router. Expansion toward 400 shared tasks is justified only if routing regret
and learning curves continue to improve.

## Files

- `data/supervisor/source-registry-v0.json`: pinned sources, licenses, intended
  uses, evidence, and quarantines.
- `data/supervisor/terminal-corpus-catalog-v0-summary.json`: exact corpus and
  frozen-benchmark coverage counts.
- `data/supervisor/companion-task-catalog-v0-summary.json`: exact gap-source
  counts and pinned Harbor registry provenance.
- `data/supervisor/aligned-task-panel-v0-summary.json`: proportional sampling
  decision and source allocation.
- `data/supervisor/terminal-pivot-checkpoints-v0-summary.json`: dynamic split,
  label, teacher, truncation, and leakage audit.
- `data/supervisor/supervisor-checkpoints-v2-summary.json`: combined
  three-source counts, quality filtering, split, and overlap audit.
- `data/supervisor/swe-pivot-overlap-audit-v0.json`: exact and normalized-text
  comparison against the pinned SWE-bench Verified holdout.
- `artifacts/training/completion-baseline-v3.json`: learning curve and held-out
  metrics for the 60/20/20 recipe.
- `docs/stage-data-results-v0.md`: the dataset-size decision and benchmark
  readiness boundary.
